# UBOS 1.0.0-RC1 Release Notes

**Release date:** 2026-07-05  
**Build number:** rc1.20260705  
**Channel:** Release Candidate  
**Package version:** 1.0.0-rc.1

UBOS 1.0.0-RC1 marks the first commercial release candidate for the Unified Live Broadcast OS. This is a stabilization release focused on production hardening, validation, packaging readiness, diagnostics, documentation, and operator confidence rather than new feature scope.

## Features

- Production Control Room coverage for production, graphics, media, replay, guests, automation, monitoring, analytics, administration, developer, AI Director, plugins, security, cloud, cluster, and settings workflows.
- Runtime architecture coverage for switching, media playback, audio, WebRTC guests, recording, rendering, monitoring, clustering, analytics, AI Director, security, cloud, and enterprise administration.
- Shared release metadata for build, package, validation, packaging, and readiness gates.
- Release report generation through `pnpm release:report`.

## Architecture

RC1 keeps the monorepo architecture split across the Next.js web control room, Fastify API, shared runtime contracts, media-plane runtime foundations, database package, configuration package, and shared UI package. Runtime validation remains contract-first: reducers, serializers, manifests, schemas, commands, events, transactions, and snapshots are treated as release gates.

## Breaking Changes

- Package versions are promoted from `0.1.0` to `1.0.0-rc.1` across the monorepo.
- The release metadata now identifies the product version as `1.0.0-RC1` and the npm-compatible version as `1.0.0-rc.1`.

## Known Limitations

- Native installer generation is metadata-ready, but signing, notarization, and store distribution must be completed in the downstream packaging pipeline.
- Hardware-specific validation depends on the target production environment and should be repeated on venue workstations before commercial deployment.
- Third-party platform API behavior may vary by account permissions, quota, and regional availability.

## Roadmap

- Promote RC1 to GA after commercial pilot validation.
- Expand automated end-to-end coverage for multi-operator Control Room flows.
- Add signed installer artifacts for Windows, macOS, Linux AppImage, DEB, and RPM targets.
- Continue performance profiling for render scheduling, panel virtualization, drag/drop latency, and workspace restore time.

## Installation

1. Install Node.js `20.9.0` or newer.
2. Install pnpm `10.28.1`.
3. Run `pnpm install`.
4. Configure environment values from `.env.example`.
5. Run `pnpm build` before deploying RC artifacts.

## Developer Notes

- Run `pnpm lint`, `pnpm typecheck`, `pnpm build`, and `pnpm test` before cutting an RC artifact.
- Run `pnpm release:report` to regenerate the production readiness report with the current Git commit.
- Treat runtime validation failures as release blockers.

## Enterprise Notes

- Validate workspace persistence, docking persistence, layout persistence, role permissions, audit expectations, and network connectivity in the customer environment.
- Confirm packaging metadata, license metadata, build metadata, and auto-update manifests before signed distribution.
- Repeat compatibility, accessibility, memory, dependency, package, and production-readiness reports for each supported deployment profile.
