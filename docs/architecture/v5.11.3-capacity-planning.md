# UBOS v5.11.3 Capacity Planning Architecture

## Ownership

`packages/core/src/capacity/index.ts` owns metadata-only capacity inventory, budgets, reservations, baselines, trends, forecasts, simulations, optimization recommendations, bottleneck analysis, upgrade planning, and immutable snapshots for v5.11.3.

## Upstream dependencies

The capacity planner reuses `@ubos/core` observability types for metric samples, alert severities, health status, and shared redaction. It does not create a scheduler, runtime loop, media clock, or alerting engine.

## Downstream consumers

Expected consumers are operational dashboards, production preflight checks, alert routing, incident response, scheduling, HA, and disaster recovery systems. The public API is explicitly exported through `@ubos/core` and `@ubos/core/capacity`.

## Generation and ownership model

Resource inventory updates require monotonically increasing `generation` values per resource. Snapshots are structured clones, reservations are bounded by available capacity, and sensitive metadata is redacted before storage.

## Failure behavior

Unsafe preflight checks return deterministic blockers and warnings. Oversubscribed reservations, stale generations, invalid capacity values, and invalid baseline windows throw explicit errors before mutating state.

## Validation

Focused validation is wired as `pnpm --filter @ubos/core validate:v5.11.3` and covers capacity calculation, stale-generation rejection, redaction, reservation conflict detection, budget enforcement, trend analysis, forecasting assumptions, saturation detection, scenario simulation, optimization recommendations, bottleneck analysis, upgrade planning, historical comparison, efficiency scoring, and snapshot publication.

## Limitations

This phase is intentionally metadata-only. It does not perform live hardware polling, automatic workload movement, or direct production launch control; those remain policy-controlled downstream integrations.
