# UBOS v5.11.4 Operational Analytics, Reporting, SLA Compliance, and Executive Dashboards

## Architectural Ownership

The v5.11.4 analytics layer is owned by `@ubos/core` under `packages/core/src/analytics/`. It is a metadata-only operational-intelligence subsystem that consumes normalized records from observability, incident response, capacity planning, and future production subsystems without owning media clocks, live runtime loops, Program/Preview state, media threads, or subsystem command authority.

## Upstream Dependencies

- Observability metric samples, alert severity, health status, and shared redaction.
- Incident-response records for evidence-linked incident analytics.
- Capacity forecasts for infrastructure trend and risk analytics.
- Future subsystem records can enter through the same bounded `AnalyticsRecord` ingestion path.

## Downstream Consumers

- Executive, engineering, producer, customer, destination, automation, and capacity dashboards.
- SLA evaluators and certified report workflows.
- Recommendation, audit, compliance, and customer-facing report delivery services.

## Processor Order and Execution Model

Analytics processing follows: ingest trusted records, normalize/redact dimensions and metadata, validate query scope, aggregate deterministically, score data quality, generate reports, evaluate SLAs, then produce recommendations. The implementation does not run on media-processing threads and does not introduce a scheduler or media clock.

## Generation and Ownership Model

Each ingested `AnalyticsRecord` carries a generation. Re-ingesting the same record with an older or equal generation is rejected, preventing stale analytics overwrites. Snapshots and returned structures are cloned so callers cannot mutate internal registries, report definitions, dashboards, agreements, or evidence lists.

## Failure Behavior

Invalid periods, non-finite metric values, unknown reports, unknown SLAs, duplicate report certification, and stale generations fail closed with explicit errors. Missing data is surfaced through `DataQualityResult` warnings and `InsufficientData` confidence instead of being treated as successful service.

## Commands and Events

The analytics API provides command-shaped methods for metric and dimension registration, ingestion, queries, report definition, report generation, report revision, report certification, report scheduling, dashboard creation, SLA creation, exclusion approval, SLA evaluation, recommendation generation, and snapshots. The bounded audit log records equivalent operational events such as metric registration, query execution, report generation, certification, dashboard creation, SLA evaluation, and exclusion approval.

## Health, Telemetry, and Watchdog

Analytics health is derived from report data-quality scores and missed SLA evaluations. Healthy status means report quality is acceptable and no SLA objective is currently missed; warning indicates degraded report evidence quality; critical indicates at least one missed SLA objective. The audit trail is bounded and metadata-only.

## Source Graph Integration

The subsystem preserves `sourceId` and `evidenceIds` on every aggregate. Reports, SLA evaluations, and recommendations retain evidence identifiers for drill-down into upstream Source Graph, incident, observability, capacity, and audit stores.

## Security and Redaction

Dimensions and metadata are redacted on ingestion. Row-level scope checks enforce customer and production filtering. Sensitive records are excluded unless the requester scope explicitly allows sensitive analytics. Certified reports are hash-stamped and cannot be silently re-certified or mutated through the certification path.

## Known Limitations

This phase implements deterministic in-memory core analytics primitives and validation coverage. Persistent warehouses, external exports, PDF rendering, email delivery, portal delivery, and digital signature providers remain integration responsibilities for later product hardening.

## Validation

The phase validation exercises aggregation, customer scoping, stale generation rejection, redaction, availability calculations, missing-data disclosure, report generation, report certification protection, dashboards, SLA breach evaluation, exclusion approval, recommendations, snapshots, and package wiring with `pnpm --filter @ubos/core validate:v5.11.4`.

## Next-Phase Handoff

v5.11.5 can build change-management and release-governance analytics on the same `AnalyticsRecord`, report, dashboard, SLA, data-quality, and evidence-drill-down abstractions without duplicating monitoring, incident, capacity, or analytics ownership.
