# UBOS v5.11.6 Security Operations Architecture

The security-operations foundation lives in `@ubos/core` and is implemented as metadata-only operational state. It reuses the v5.11 observability redaction and health types and integrates with the v5.11 incident-response engine through typed alert and incident creation.

## Ownership

`SecurityOperationsCenter` owns bounded security event storage, threat correlation, identity risk, device trust, vulnerability inventory, immutable evidence records, compliance findings, containment policy evaluation, security reports, sanitized audit metadata, and security health telemetry.

## Determinism and safety

Inputs are sorted deterministically before scoring, snapshots are immutable clones, evidence IDs are write-once, local verified security events drive threat scoring, and threat intelligence can only add context. Containment actions are policy-controlled, authorization-aware, auditable, and preserve production continuity metadata.

## Existing abstractions reused

- `@ubos/core/observability` for `HealthStatus`, `AlertSeverity`, and `redact`.
- `@ubos/core/incident-response` for operational alert and incident integration.
- Existing package validation scripts, explicit public exports, and bounded metadata-only snapshot patterns.
